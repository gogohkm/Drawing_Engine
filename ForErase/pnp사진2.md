작성해서 실행해보니 잘되는데  내가 생각한 것과는 달라 예를들어 첨부한 이미지와 같은 사진이 있을 경우 이 사진을 2d로 dxf파일에 cad로 보이는 그대로 그려주고, 이 도면에서 2점을 선택하면 p2p기능처럼 두 점사이 거리를 3차원으로 예측해서 그리고 싶어. 가능한 방법이 있으면 알려줘. 

가능은 한데, **“사진 1장만 가지고 2점 사이의 ‘진짜 3D 거리’를 일반적으로 정확하게 예측”**하는 건 추가 정보 없이는 원리적으로 불가능에 가깝습니다. (한 장의 원근 사진은 깊이 정보가 무한히 여러 해로 성립)

다만 현실적으로 쓸만한 방법이 몇 가지 있어요. 아래는 “네가 원하는 UX(사진→2D로 그려주고, 2점 찍으면 P2P처럼 3D 거리)”를 기준으로, 가능한 구현 경로를 정확도 순으로 정리한 겁니다.

⸻

1) 먼저 네가 원하는 기능을 분해하면

A. 사진을 “CAD에서 보이는 그대로” 2D DXF로 트레이싱
	•	이건 가능.
	•	결과 DXF는 “실제 정면도/평면도”가 아니라 사진의 투영(원근) 좌표계에서의 2D 도면이 됨.

B. 그 2D 도면에서 2점을 고르면 “3D 거리”를 뽑기
	•	여기서 핵심은: **그 2D 좌표(픽셀/투영좌표)를 3D 점으로 ‘복원’**해야 함.
	•	복원하려면 추가 제약/정보가 꼭 필요.

⸻

2) 가능한 방법들 (정확도 높은 순)

방법 1) 여러 장(또는 영상)으로 3D 복원(포토그래메트리/SLAM) ✅ 가장 정석
	•	같은 구조물을 서로 다른 위치에서 찍은 사진 20~100장(또는 스마트폰 영상)으로
	•	COLMAP 같은 포토그래메트리로 카메라 자세 + 희소 3D 포인트/메시를 얻음
	•	사용자가 2점을 찍으면 그 점의 3D 좌표를 찾아서 거리 계산

장점
	•	“임의의 2점”도 3D 거리 가능
	•	정밀도(스케일만 맞추면) 꽤 좋음

단점
	•	사진 여러 장 필요
	•	파이프라인이 좀 무거움(하지만 한번 붙이면 강력)

실무 팁
	•	스케일은 현장에 기준 길이(예: 기둥 간격, 볼트 피치, 문 폭) 하나만 알아도 맞출 수 있음.

⸻

방법 2) 단일 사진 + ‘깊이(Depth) 모델’ + 스케일 1개 (빠른 근사)
	•	MiDaS 같은 단안 depth 추정 모델로 사진의 픽셀별 상대깊이(depth map)를 추정
	•	사용자가 2점을 찍으면 각 픽셀에 대해 광선(ray)을 만들고
depth로 3D 점을 근사 복원 → 거리 계산
	•	스케일은 알려진 실제 길이 1개(예: H빔 간격 6m 등)로 보정

장점
	•	사진 1장으로 UX 구현 가능
	•	“대략적인 3D 거리”는 뽑힘

단점(중요)
	•	정확도는 케이스 바이 케이스 (특히 철골 프레임/반복 패턴에서 깊이 착시로 흔들릴 수 있음)
	•	“정밀 측정” 용도로는 한계

👉 너 목표가 “P2P처럼 신뢰할 측정”이면, 이건 보조/초기 기능 정도로 보는 게 맞아요.

⸻

방법 3) 단일 사진 + 기하학 제약(Manhattan/평면/대칭/규격)으로 복원 (구조물 특화)

첨부 사진 같은 철골 골조는 제약이 많아서, 단일 사진도 어느 정도 가능해집니다.

예를 들면:
	•	구조가 **맨해튼 월드(서로 직교하는 방향 3개)**에 가깝다
	•	지붕/벽/바닥 등 평면이 있다
	•	프레임 반복 간격(베이 간격) 같은 규격값이 있다

이 경우 할 수 있는 것:
	1.	사진에서 주요 직선들을 찾아 소실점(vanishing point) 2~3개 추정
	2.	카메라 내부파라미터 K를 대략 복원(또는 입력)
	3.	“바닥면 Z=0”, “정면 프레임면” 같은 기준 평면을 잡음
	4.	사용자가 찍은 점이 어느 평면 위에 있다고 선택하면
그 평면과 광선의 교차로 3D 좌표를 얻고 거리 계산

장점
	•	사진 1장, 그래도 “규칙적인 구조물”에서는 꽤 쓸만함
	•	정확도를 올리려면 기준 길이 1개(베이 간격 등)만 있으면 됨

단점
	•	“임의의 점”이 아니라, 점이 어느 평면/부재 위인지를 알아야 함
(예: “바닥 위 점”, “정면 프레임 평면 위 점”, “지붕 평면 위 점”…)
	•	완전 자동화는 난이도 높음 → UX로 “점의 소속 평면 선택”을 넣으면 실용화 쉬움

⸻

3) 너가 원하는 UX에 딱 맞춘 “현실적인 구현안”

핵심 아이디어: 2D로 그리되, 측정은 ‘평면 선택’ 방식으로 3D화
	1.	사진을 웹뷰에 띄우고 선을 따서 **“사진 좌표계 DXF(원근 상태)”**로 그린다
	•	이건 지금도 잘 되고 있다고 했지? (edge/line detection + DXF polyline)
	2.	사용자가 도면에서 점 2개를 찍으면,
	3.	UI에서 “이 점은 어느 평면 위인가?”를 선택하게 한다:
	•	바닥면(Z=0)
	•	정면 프레임 평면
	•	좌측 벽 평면
	•	지붕 평면
	•	(커스텀: 3점 찍어 평면 정의)
	4.	각 점에 대해 ray–plane intersection으로 3D 좌표를 만들고,
	5.	두 점의 3D 거리 계산 → P2P처럼 표시

이렇게 하면 “사진 1장 + P2P 3D 측정”이 실무적으로 성립합니다.
(단, 점이 “같은 평면” 위라는 가정이 들어가야 정확해짐)

⸻

4) “완전 자동 P2P 3D”를 하고 싶다면 필요한 최소 추가정보

아래 중 하나만 더 있으면, 퀄리티가 확 올라가요.
	•	(가장 쉬움) 기준 길이 1개: 예) 베이 간격 6,000mm / 기둥 간 거리 / 문 폭
	•	(좋음) 사진 2장 이상(또는 영상)
	•	(최고) 아이폰 LiDAR/깊이카메라 데이터(ARKit/ARCore depth)

⸻

5) 다음 단계 추천 (너 상황 기준)

네가 이미 “PnP 정합이 잘 된다”고 했으니, 가장 빠른 확장은 이거예요:

✅ (1) 사진 좌표계 DXF 생성(원근 그대로)
✅ (2) 점 2개 선택
✅ (3) ‘평면 선택’ UI 추가
✅ (4) ray-plane로 3D 좌표 계산 후 P2P 표시
✅ (5) 기준 길이 1개로 스케일 고정(선택)

⸻

원하면 내가 바로 이어서,
	•	평면 선택 UI 설계(최소 클릭)
	•	평면 정의 방식 3종(고정 평면 / 3점 평면 / CAD에서 면 선택)
	•	2점 선택 → 3D P2P 계산 수식 + 백엔드 API 명세
까지 “표준 구현안”으로 한 번에 써줄게.

대신 한 가지만 딱 말해줘:
	•	너 DXF는 실제 CAD 좌표(mm) 기반이야?
아니면 “사진 원근 좌표계(픽셀 기반)”로 그린 DXF야?
(둘 다 가능하지만, P2P 3D 쪽 처리 흐름이 약간 달라져.)

좋아요. DXF가 “사진 원근 좌표계(=이미지 평면 좌표)” 기반이라면, 네가 원하는 건 이렇게 정리돼요:
	1.	사진에서 보이는 선들을 따서 그대로(원근 유지) 2D DXF로 그림
	2.	DXF에서 2점을 찍으면 **P2P처럼 “3D 거리”**를 예측해 표시

여기서 핵심은:
	•	DXF 좌표 = 사실상 픽셀 좌표(u,v) 와 동치(스케일만 다를 뿐)
	•	그런데 (u,v)만으로는 깊이(Z)가 없음 → “3D 복원”에는 추가 제약이 필요

그래서 “가능한 방법”은 제약을 UX로 넣어주는 방식이 가장 현실적입니다.

⸻

결론부터: 가장 현실적인 구현안(단일 사진, 원근 DXF)

✅ “평면(Plane) 기반 P2P”로 만든다 (추천)

사용자가 2점을 찍을 때, 각 점이 어느 평면 위인지만 지정해주면 3D 거리까지 갈 수 있어요.
	•	평면 예시
	•	바닥면(지면)
	•	정면 프레임 면(포털 프레임 평면)
	•	측벽 면
	•	지붕면

왜 이게 되냐?

점이 평면 위에 있다고 가정하면,
	•	점의 픽셀(u,v) → 카메라에서 나가는 광선(ray)
	•	광선과 “그 평면”의 교차점 = 그 점의 3D 좌표
	•	두 점의 3D 좌표가 나오면 거리 계산 끝

⸻

구현 흐름(표준)

STEP 0) DXF 좌표계를 “픽셀 좌표계”로 정의

지금 DXF는 원근 좌표계라고 했으니,
	•	DXF에서 선택한 점 (x_dxf, y_dxf)를
	•	이미지 픽셀 (u,v)로 변환만 하면 됩니다.

보통은 DXF 생성할 때 썼던 스케일/원점이 있으니:
	•	u = (x_dxf - ox) / s
	•	v = (y_dxf - oy) / s
(또는 반대로)

👉 중요: 이 스케일/원점/이미지 W,H를 DXF 메타로 같이 저장해두면 P2P가 쉬워져요.

⸻

STEP 1) “카메라 모델”을 잡는다 (K 추정 + 왜곡 옵션)

PnP까지 안 가도 되고, 최소한 아래는 필요합니다.
	•	K = [[fx,0,cx],[0,fy,cy],[0,0,1]]
	•	(가능하면) 왜곡 dist

초기 MVP는:
	•	cx=W/2, cy=H/2
	•	fx=fy≈0.9*max(W,H)
	•	dist=0
로 시작 가능

정밀도를 올리려면:
	•	휴대폰 광각이면 dist 보정(캘리브레이션) 추천

⸻

STEP 2) “평면(Plane) 정의”를 사용자 입력으로 만든다

여기서 선택지가 2개예요.

방법 A) 평면에 있는 직사각형 4점 + 실제 치수 1~2개 (제일 쉽고 강력)

예: 정면 프레임 면에서
	•	네 모서리 4점을 찍게 하고
	•	실제 폭(스팬) 또는 높이(처마고) 같은 기준 길이 1개 이상 입력

그러면:
	•	그 평면의 호모그래피(H) 를 구해서
	•	이미지 좌표(u,v) ↔ 평면 좌표(X,Y)로 바꿀 수 있음
	•	즉 그 평면 위 점들의 **“실측 좌표(단위 mm)”**가 나옵니다.

👉 이 방식은 OpenCV 없어도 JS로도 가능하지만, 백엔드(OpenCV/Python)가 더 편해요.

방법 B) 맨해튼(직교) 가정 + 소실점 (자동화 욕심낼 때)

철골 골조 사진은 보통
	•	길이방향, 폭방향, 수직방향이 거의 직교 → 소실점 2~3개 추정 가능
이걸로 K/자세 일부를 더 안정적으로 잡을 수 있어요.

하지만 MVP는 A가 훨씬 빨라요.

⸻

STEP 3) P2P 동작(사용자 2점 선택 → 3D 거리)

가장 실무적인 UX
	•	사용자가 점 1, 점 2를 찍는다
	•	각 점마다 “이 점은 어느 평면?”을 선택한다
	•	같은 평면이면 매우 정확
	•	서로 다른 평면이면 “두 평면의 상대 위치” 정보가 추가로 필요

계산
	•	(같은 평면일 때)
	•	H로 (u,v) → 평면좌표(X,Y) 변환
	•	그 평면을 3D에서 Z=0으로 놓으면 3D는 (X,Y,0)
	•	거리 = 2D 평면거리 = 3D 거리(평면 위 거리)
	•	(다른 평면일 때)
	•	두 평면 각각에서 3D 좌표를 만들 수 있어야 함
	•	이때는 “평면의 3D 위치/각도 관계”가 필요합니다.
	•	현실적으로는 아래 중 하나가 추가 입력으로 필요:
	1.	평면끼리 만나는 선(예: 정면 프레임과 바닥의 교선) 지정 + 기준 높이 1개
	2.	구조의 알려진 치수(기둥 높이, 베이 간격 등) 추가 1개
	3.	사진 2장(가장 깔끔)

⸻

네가 원하는 “철골 골조 사진”에 딱 맞는 MVP 제안

MVP-1 (가장 빨리 성공)

✅ 정면 프레임 평면만 먼저 지원
	1.	사용자가 정면 프레임의 네 모서리 4점(예: 좌/우 기둥 상단, 좌/우 기둥 하단)을 찍음
	2.	실제 스팬(예: 20,000mm) 입력
	3.	이제 정면 프레임 면 위에서 찍는 모든 점은 실측 좌표(mm) 로 변환 가능
	4.	두 점 거리(P2P) = 정면 프레임 면에서의 실측 거리

→ “CAD처럼 보이는 그대로 따고, 치수도 그럴듯하게” 바로 체감 나옵니다.

MVP-2 (확장)
	•	바닥면, 지붕면도 같은 방식으로 평면 하나씩 추가
	•	각 평면마다 “4점 + 기준치수”로 H와 스케일 저장

MVP-3 (진짜 3D P2P에 가까워짐)
	•	“평면들 사이 관계”를 추가로 정의:
	•	정면 프레임 면과 바닥면이 직교
	•	기둥 높이 H_known 입력
	•	바닥과 정면 프레임의 교선(기둥 베이스 라인) 지정
이 정도면 서로 다른 평면 점 사이 거리도 꽤 그럴듯하게 계산할 수 있어요.

⸻

현실적인 한계(정직하게)
	•	사진 1장 + 임의 2점 = 진짜 3D 거리는 추가정보 없이는 불가능
	•	하지만 네가 다루는 구조물은 규격/직교/평면이 뚜렷해서
**“평면 기반 + 기준치수”**만 넣어도 실무적으로 쓸만한 “P2P 같은 측정”이 됩니다.

다음에 내가 바로 써줄 수 있는 것(선택)

원하면 내가 다음 메시지에 표준 구현안(API+데이터구조+연산식) 을 딱 맞게 써줄게.
너는 “원근 DXF”라고 했으니 아래 중 하나로 바로 갈 수 있어요:
	1.	정면 프레임 평면 MVP: 4점 + 스팬 1개로 P2P(mm) 구현 (가장 추천)
	2.	다중 평면(바닥/지붕/정면) + 평면 선택 P2P
	3.	서로 다른 평면 사이 3D P2P까지(추가 기준치수 1~2개 포함)

지금 상황에선 1)부터가 가장 빠르게 “원하는 느낌”이 나옵니다.

좋아요. 1번(MVP-1): “정면 프레임 평면”만으로 P2P(mm) 거리가 나오게 하는 표준 구현안을 아래에 “바로 붙여넣어 쓸 수 있는 수준”으로 정리해줄게요.

핵심은 PnP가 아니라 Homography(평면 변환 H) 입니다.
	•	DXF는 “사진 원근 좌표계” → 사실상 (u,v) 픽셀 좌표와 동치
	•	정면 프레임은 하나의 평면
	•	그 평면에서의 2D 좌표계를 만들면 실측(mm) 좌표로 변환 가능
	•	두 점의 거리 = 그 평면에서의 거리(mm)

⸻

MVP-1 목표
	1.	사진을 그대로 트레이싱해서 “원근 DXF” 생성 (이미 됨)
	2.	사용자가 정면 프레임 평면의 기준점 4개를 찍고
	3.	**스팬(실제 폭) 1개(mm)**를 입력하면
	4.	도면에서 임의의 2점을 찍을 때마다 **P2P 거리(mm)**를 표시

정면 프레임 “면 위의 점”들만 정확합니다. (기둥/보/가새 등 정면 프레임에 있는 요소)

⸻

0) 좌표계 정의 (중요)

DXF 좌표를 이미지 픽셀로 바꾸는 함수가 필요합니다.
	•	너의 DXF가 “사진 원근 좌표계”라면, DXF 생성 시 사용한
	•	scale s
	•	origin (ox, oy)
	•	이미지 크기 W,H
을 메타로 저장해두고,
u = (x_dxf - ox) / s
v = (y_dxf - oy) / s

반대로 픽셀→DXF는
x_dxf = ox + s*u
y_dxf = oy + s*v

※ DXF에서 점 2개 선택 후 P2P는, 내부 계산은 **(u,v)**로 하는 게 가장 깔끔합니다.

⸻

1) 사용자가 찍을 4개 기준점(정면 프레임)

사용자가 사진(또는 DXF)에서 다음 4점을 “정면 프레임 면 위”에서 찍게 합니다.

권장 예시(사각형이 되도록):
	•	A: 좌측 기둥 하단(바닥선과 기둥의 교점)
	•	B: 우측 기둥 하단
	•	C: 우측 기둥 상단(처마/라프터 시작점)
	•	D: 좌측 기둥 상단

그리고 실제 스팬 L(mm) 입력:
	•	L = 거리(A,B) 실측 (예: 20000mm)

높이(H)를 입력받으면 더 좋지만, MVP-1은 스팬 1개로도 충분히 “P2P 느낌”을 만들 수 있어요.
(단, 프레임의 수직방향 mm 스케일은 스팬 기준으로 결정되므로, 카메라가 비스듬하면 높이 쪽 오차가 커질 수 있음 → 추후 높이 1개 추가하면 보정됩니다.)

⸻

2) Homography 설계 (핵심)

정면 프레임 평면에 “가상의 평면 좌표계(미터/mm)”를 정의합니다.
	•	평면 좌표계에서:
	•	A′ = (0, 0)
	•	B′ = (L, 0)
	•	C′ = (L, Ly)  ← 여기서 Ly는 모름
	•	D′ = (0, Ly)

문제: Ly(높이 방향 스케일)가 없으면 H가 완전히 정해지지 않냐?
→ H는 4점 대응으로 구해지는데, 목적지 좌표(C′,D′)의 y값을 임의로 두면 결과는 “mm가 아닌 임의단위”가 됩니다.

그래서 MVP-1은 이렇게 합니다:

MVP-1의 트릭(표준 실무 트릭)
	1.	먼저 목적지 사각형의 높이 Ly를 픽셀에서의 상대비로 설정하고
	2.	마지막에 “스팬 L로 x축 스케일을 mm로 고정”합니다.

구체적으로:
	•	픽셀에서 A-B 길이(픽셀) = lenAB_px
	•	픽셀에서 A-D 길이(픽셀) = lenAD_px
	•	상대 높이비 r = lenAD_px / lenAB_px
	•	목적지 사각형 높이를 Ly = r * L 로 둔다

그러면,
	•	x방향은 반드시 L(mm)로 맞고
	•	y방향도 “사진에서의 비율”을 따라가므로
	•	정면 프레임 면 위의 거리들은 꽤 자연스럽게 mm로 나옵니다.

더 정확한 y 스케일이 필요하면 나중에 “실제 높이 H(mm)”도 추가해서 Ly를 H로 고정하면 됩니다(확장 쉬움).

backend/frame_plane.py

import numpy as np
import cv2

def _to_homog(pt2):
    x, y = float(pt2[0]), float(pt2[1])
    return np.array([x, y, 1.0], dtype=np.float64)

def apply_H(H, uv):
    H = np.asarray(H, dtype=np.float64)
    p = _to_homog(uv)
    q = H @ p
    if abs(q[2]) < 1e-12:
        return None
    return [float(q[0]/q[2]), float(q[1]/q[2])]

def calibrate_frame_plane(A, B, C, D, span_mm):
    # A,B,C,D are image pixel coords [u,v]
    A = np.asarray(A, dtype=np.float64)
    B = np.asarray(B, dtype=np.float64)
    C = np.asarray(C, dtype=np.float64)
    D = np.asarray(D, dtype=np.float64)

    L = float(span_mm)

    lenAB = float(np.linalg.norm(B - A))
    lenAD = float(np.linalg.norm(D - A))
    if lenAB < 1e-6:
        raise ValueError("A and B too close")

    r = lenAD / lenAB
    Ly = r * L  # MVP-1: y scale from image ratio

    src = np.array([A, B, C, D], dtype=np.float64)  # image
    dst = np.array([[0,0], [L,0], [L,Ly], [0,Ly]], dtype=np.float64)  # plane (mm)

    H, _ = cv2.findHomography(src, dst, method=0)  # direct from 4 points
    if H is None:
        raise ValueError("findHomography failed")

    Hinv = np.linalg.inv(H)
    return H.tolist(), Hinv.tolist(), L, Ly

def p2p_distance_mm(H_img_to_plane, P1, P2):
    X1 = apply_H(H_img_to_plane, P1)
    X2 = apply_H(H_img_to_plane, P2)
    if X1 is None or X2 is None:
        return None
    dx = X2[0] - X1[0]
    dy = X2[1] - X1[1]
    dist = float(np.hypot(dx, dy))
    return X1, X2, dist

backend/main.py (추가 라우트)

from fastapi import FastAPI
from pydantic import BaseModel
from typing import List
from frame_plane import calibrate_frame_plane, p2p_distance_mm

app = FastAPI()

class CalibReq(BaseModel):
    A: List[float]
    B: List[float]
    C: List[float]
    D: List[float]
    span_mm: float

@app.post("/frame/calibrate")
def frame_calibrate(req: CalibReq):
    H, Hinv, Lx, Ly = calibrate_frame_plane(req.A, req.B, req.C, req.D, req.span_mm)
    return {"ok": True, "H_img_to_plane": H, "H_plane_to_img": Hinv, "Lx_mm": Lx, "Ly_mm": Ly}

class P2PReq(BaseModel):
    H_img_to_plane: List[List[float]]
    P1: List[float]
    P2: List[float]

@app.post("/frame/p2p")
def frame_p2p(req: P2PReq):
    res = p2p_distance_mm(req.H_img_to_plane, req.P1, req.P2)
    if res is None:
        return {"ok": False, "error": "transform failed"}
    X1, X2, dist = res
    return {"ok": True, "P1_plane": X1, "P2_plane": X2, "distance_mm": dist}

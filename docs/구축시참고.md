# 3D 복원 구축 시 참고사항

OpenCV 샘플 프로젝트와 COLMAP 분석을 통해 배운 점을 정리합니다.

---

## 1. 핵심 원리: 단일 사진 vs 다중 사진

### 단일 사진의 한계

**수학적으로 정보가 부족합니다.**

- 2D 이미지 → 3D 복원은 **역문제(Inverse Problem)**
- 하나의 픽셀 (u, v)에 대응하는 3D 점은 **무한히 많음** (카메라로부터의 광선 위의 모든 점)
- 깊이(Depth) 정보가 손실되어 있음

```
[3D 세계]          [2D 이미지]
(X, Y, Z) ────────→ (u, v)
    ↑                  │
    │   정보 손실      │
    └──────────────────┘
       복원 불가능
```

### 다중 사진이 필요한 이유

**삼각측량(Triangulation)** 원리:
- 서로 다른 위치에서 촬영한 2장 이상의 사진
- 동일한 점을 두 사진에서 찾으면 (매칭)
- 두 광선의 교점으로 3D 위치 계산 가능

```
카메라1 ──────●────────→
              │
              │ 3D 점
              │
카메라2 ──────●────────→
```

## 2. OpenCV 샘플에서 배운 방법들

### 2.1 카메라 캘리브레이션 (calibrate.py)

**목적**: 카메라 내부 파라미터(K)와 왜곡 계수 계산

**방법**:
1. 체스보드 또는 ChArUco 보드 사용
2. 여러 각도에서 촬영
3. 코너 검출 → `cv.calibrateCamera()`

**핵심 코드**:
```python
# 체스보드 코너 검출
found, corners = cv.findChessboardCorners(img, pattern_size)
cv.cornerSubPix(img, corners, (5, 5), (-1, -1), term)

# 카메라 캘리브레이션
rms, camera_matrix, dist_coefs, rvecs, tvecs = cv.calibrateCamera(
    obj_points, img_points, (w, h), None, None
)
```

**결과물**:
- `camera_matrix` (K): 3x3 내부 행렬 (fx, fy, cx, cy)
- `dist_coefs`: 왜곡 계수
- `rvecs`, `tvecs`: 각 이미지의 카메라 자세

**우리 프로젝트 적용**:
- 사용하는 카메라/스마트폰의 K 행렬을 미리 캘리브레이션
- 또는 EXIF에서 focal length 추출하여 추정

### 2.2 Essential Matrix 3D 복원 (essential_mat_reconstr.py)

**목적**: 2장 사진에서 3D 점 복원

**전제 조건**:
- 카메라 내부 행렬 K를 알고 있어야 함
- 두 이미지 간 충분한 특징점 매칭 필요

**파이프라인**:
```
[이미지1] ──→ SIFT 특징점 ──→ FLANN 매칭 ──→ Lowe Ratio Test
[이미지2] ──→ SIFT 특징점 ──┘
                                    ↓
                           Essential Matrix (E)
                                    ↓
                           R, t 분해 (4가지 해)
                                    ↓
                           Triangulation
                                    ↓
                           3D Point Cloud
```

**핵심 코드**:
```python
# 1. 특징점 추출 및 매칭
detector = cv.SIFT_create(nfeatures=20000)
keypoints1, descriptors1 = detector.detectAndCompute(image1, None)
matcher = cv.FlannBasedMatcher(dict(algorithm=0, trees=5), dict(checks=32))
matches = matcher.knnMatch(descriptors1, descriptors2, k=2)

# 2. Lowe Ratio Test (좋은 매칭만 필터링)
for m in matches:
    if m[0].distance / m[1].distance < 0.75:
        good_matches.append(m[0])

# 3. Essential Matrix 계산
E, inliers = cv.findEssentialMat(pts1, pts2, K, cv.RANSAC, 0.999, 1.0)

# 4. R, t 분해
R1, R2, t = cv.decomposeEssentialMat(E)

# 5. Triangulation
P1 = np.concatenate((K, np.zeros((3,1))), axis=1)  # K[I|0]
P2 = np.dot(K, np.concatenate((R1, t), axis=1))    # K[R|t]
obj_pt = cv.triangulatePoints(P1, P2, pt1, pt2)
```

**중요 포인트**:
- Essential Matrix는 **스케일 정보가 없음** (up to scale)
- 실제 거리를 알려면 기준점 하나의 실제 거리가 필요
- 4가지 (R, t) 조합 중 **positive depth** 조건으로 선택

### 2.3 스테레오 매칭 (stereo_match.py)

**목적**: 스테레오 카메라로 깊이 맵 생성

**전제 조건**:
- 두 카메라가 수평으로 정렬 (Rectified)
- 베이스라인(두 카메라 간 거리) 알고 있음

**원리**:
```
깊이 = (focal_length × baseline) / disparity
```

**핵심 코드**:
```python
# Semi-Global Block Matching
stereo = cv.StereoSGBM_create(
    minDisparity=16,
    numDisparities=96,
    blockSize=16,
    P1=8*3*window_size**2,
    P2=32*3*window_size**2
)

# Disparity 계산
disp = stereo.compute(imgL, imgR).astype(np.float32) / 16.0

# 3D 재투영
Q = np.float32([[1, 0, 0, -0.5*w],
                [0,-1, 0,  0.5*h],
                [0, 0, 0,     -f],
                [0, 0, 1,      0]])
points = cv.reprojectImageTo3D(disp, Q)
```

**우리 프로젝트 적용 가능성**:
- 스테레오 카메라가 없으면 사용 불가
- 대안: 카메라를 수평으로 이동하며 2장 촬영

### 2.4 Homography 평면 추적 (plane_tracker.py)

**목적**: 평면 객체 추적 및 자세 추정

**원리**:
- 평면은 Homography(3x3 행렬)로 완전히 기술 가능
- 4개 이상의 대응점으로 계산

**핵심 코드**:
```python
class PlaneTracker:
    def track(self, frame):
        # ORB 특징점 매칭
        matches = self.matcher.knnMatch(frame_descrs, k=2)

        # Lowe Ratio Test
        matches = [m[0] for m in matches
                   if len(m) == 2 and m[0].distance < m[1].distance * 0.75]

        # Homography 계산
        H, status = cv.findHomography(p0, p1, cv.RANSAC, 3.0)

        # 평면 영역 변환
        quad = cv.perspectiveTransform(quad.reshape(1, -1, 2), H)
```

**중요 포인트**:
- `cv.findHomography()`는 RANSAC으로 outlier 제거
- 최소 4점 필요, 더 많으면 정확도 향상
- **평면에서만 유효** (3D 물체에는 사용 불가)

## 3. COLMAP에서 배운 점

### 3.1 Structure-from-Motion (SfM) 파이프라인

```
[다수의 이미지]
      ↓
Feature Extraction (SIFT)
      ↓
Feature Matching (Exhaustive 또는 Vocabulary Tree)
      ↓
Incremental Reconstruction
  ├── Initial Pair Selection
  ├── Triangulation
  ├── Camera Registration (PnP)
  └── Bundle Adjustment
      ↓
[3D Point Cloud + Camera Poses]
      ↓
(Optional) Multi-View Stereo → Dense Reconstruction
```

### 3.2 핵심 함수들 (pycolmap)

```python
import pycolmap

# 특징점 추출
pycolmap.extract_features(database_path, image_path)

# 특징점 매칭
pycolmap.match_exhaustive(database_path)

# Incremental SfM
reconstructions = pycolmap.incremental_mapping(
    database_path,
    image_path,
    sfm_path,
    initial_image_pair_callback=...,
    next_image_callback=...
)

# 결과 확인
for idx, rec in reconstructions.items():
    print(rec.summary())
```

### 3.3 우리 프로젝트와의 관계

COLMAP은 **완전히 다른 문제**를 풀고 있음:
- 입력: 수십~수백 장의 다양한 각도 사진
- 출력: 완전한 3D 모델 + 모든 카메라 자세

우리 문제:
- 입력: 1장의 실내 사진
- 출력: 도면 (바닥 평면도)

**직접 적용은 어렵지만**, Bundle Adjustment 개념은 참고할 만함.

## 4. 우리 프로젝트에 적용 가능한 방법

### 4.1 단일 사진 + 평면 Homography (현실적 선택)

**원리**:
- 바닥면은 하나의 평면 (Z = 0)
- 4개 코너의 픽셀 좌표 + 실제 좌표를 알면 Homography 계산 가능
- 바닥면 위의 모든 점을 실제 좌표로 변환

**필요 정보**:
1. 바닥면 4개 코너의 **픽셀 좌표** (이미지에서 클릭)
2. 그 중 **하나의 실제 거리** (예: 가로 10m)

**구현**:
```python
def calibrate_floor_plane(corners_pixel, width_mm):
    """
    corners_pixel: [(u1,v1), (u2,v2), (u3,v3), (u4,v4)]
                   순서: 좌상, 우상, 우하, 좌하
    width_mm: 가로 실제 길이 (mm)
    """
    # Metric Rectification으로 높이 추정
    # ...

    # Homography 계산
    src = np.array(corners_pixel, dtype=np.float64)
    dst = np.array([[0, 0], [width_mm, 0],
                    [width_mm, height_mm], [0, height_mm]], dtype=np.float64)
    H, _ = cv2.findHomography(src, dst)

    return H
```

### 4.2 단일 사진 + 다중 평면 (벽면 포함)

**원리**:
- 바닥면: Z = 0 평면
- 뒷벽면: Y = far_depth 평면
- 좌/우 벽면: X = ±width/2 평면

**각 평면별로 별도 Homography 필요**

```python
# 바닥면 Homography
H_floor = calibrate_plane(floor_corners, floor_size)

# 뒷벽면 Homography
H_back_wall = calibrate_plane(wall_corners, wall_size)

# 픽셀이 어느 평면에 속하는지 판단
def get_plane_for_pixel(u, v, horizon_y):
    if v > horizon_y:
        return 'floor'
    else:
        return 'wall'
```

### 4.3 2장 사진 Essential Matrix (권장)

**장점**:
- 실제 3D 구조 복원 가능
- 바닥뿐 아니라 물체도 측정 가능

**필요 조건**:
1. 같은 공간을 **다른 위치**에서 2장 촬영
2. 카메라 K 행렬 (EXIF에서 추출 또는 캘리브레이션)
3. 기준 거리 1개 (스케일 결정용)

**구현 방향**:
```python
def reconstruct_3d_from_two_images(img1_path, img2_path, K, reference_distance):
    # 1. 특징점 추출
    kp1, desc1 = sift.detectAndCompute(img1)
    kp2, desc2 = sift.detectAndCompute(img2)

    # 2. 매칭 + Lowe Test
    matches = match_features(desc1, desc2)

    # 3. Essential Matrix
    E, mask = cv2.findEssentialMat(pts1, pts2, K)

    # 4. R, t 복원
    _, R, t, mask = cv2.recoverPose(E, pts1, pts2, K)

    # 5. Triangulation
    points_3d = triangulate(pts1, pts2, K, R, t)

    # 6. Scale 조정 (reference_distance 사용)
    scale = reference_distance / computed_distance
    points_3d *= scale

    return points_3d
```

## 6. 기억해야 할 공식들

### Homography 적용
```python
# 픽셀 (u, v) → 평면 좌표 (X, Y)
p_img = [u, v, 1]
p_plane = H @ p_img
X, Y = p_plane[0]/p_plane[2], p_plane[1]/p_plane[2]
```

### Essential Matrix에서 R, t
```python
E, mask = cv2.findEssentialMat(pts1, pts2, K, cv2.RANSAC, 0.999, 1.0)
R1, R2, t = cv2.decomposeEssentialMat(E)
# 4가지 조합 중 positive depth 선택
```

### Triangulation
```python
P1 = K @ [I | 0]      # 첫 번째 카메라
P2 = K @ [R | t]      # 두 번째 카메라
X = cv2.triangulatePoints(P1, P2, x1, x2)
X = X[:3] / X[3]      # Homogeneous → Euclidean
```

### PnP (3D→2D 대응으로 카메라 자세)
```python
success, rvec, tvec = cv2.solvePnP(obj_points_3d, img_points_2d, K, dist_coeffs)
R, _ = cv2.Rodrigues(rvec)
```

## 8. 결론

**단일 사진에서 정확한 3D 복원은 수학적으로 불가능합니다.**

가능한 선택지:
1. **평면 가정 + Homography**: 바닥면만 정확히 측정 (현실적)
2. **2장 사진 + Essential Matrix**: 완전한 3D 복원 (권장)
3. **다중 사진 + SfM**: 가장 정확하지만 복잡 (과잉)

우리 프로젝트는 **도면화**가 목적이므로, **Phase 1 (바닥면 Homography)**부터 완성하고 점진적으로 확장하는 것이 현실적입니다.
